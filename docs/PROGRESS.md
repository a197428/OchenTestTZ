## Фаза 1. Ингест библиотеки — выполнено 2026-11-10

**Сделано**

- `scripts/ingest/svg.ts`: парсинг (`@xmldom/xmldom`), `fixId`, поиск групп, сбор путей,
  bbox (`svg-path-bbox`), подписи форм, МНК-подгонка S→L, hull ≤64 точек.
- `scripts/ingest/library.ts`: 10 объектов × 2 состояния × 2 размера, hex→слот по purple,
  проверка числа путей, alias, `toNative`, выпуклые оболочки, `catalog.json` + 28 фрагментов.
- `scripts/ingest/substrates.ts`: `confetti` (purple) и `diagonal` (orange), слоты, origin,
  fallback для wide/tall (cover 1000×1000 до Фазы 2).
- `scripts/facts.ts`: 10 проверок (пути, палитры-свотчи, масштабы, alias, 18 кадров,
  teal-оракул подложки, инвариант слотов, свежесть generated).
- `tests/unit/catalog.test.ts`: инварианты каталога и фрагментов.
- `pnpm verify` теперь включает `pnpm facts`.

**Результаты**

- 28 вариантов, 12 alias (все фоновые состояния + `lamp.main`, `tulips.main`).
- Масштабы S→L: ×2,000 у книги, телефона, пазлов, наушников, лампы, кошелька, ручки,
  папки; ×1,8812 у монеты; ×1,8269 у тюльпанов. Максимальная невязка МНК 0,0195 px.
- Книга: масштаб ×2,000 (факт `[VERIFY]` подтверждён).
- Ингест идемпотентен (побайтовое сравнение generated), `d` путей дословно из источника.

**Удивило**

- У книги в S «лишний» путь лежит **внутри** обёрточной группы (`Vector_269` /
  `Vector_833`), а в L — на корне листа. Отбрасывается по id; после этого counts 50/53.
- Подписи по контрольным точкам (приложение B) дают мало совпадений: S и L экспорты
  по-разному сегментируют кривые. Матчинг переведён на сэмплирование по длине пути.
- Фоновые объекты тоже потребовали alias-порога: у 7 путей монеты S-размер < 0,5 px.

**Отложено**

- Подложки для wide/tall берутся fallback-масштабом из square; извлечение по форматам
  из «Примеров» — Фаза 2.
- `scripts/ingest/examples.ts`, `fit.ts` — заготовки для Фазы 2.

## Фаза 2. Ингест примеров — выполнено 2026-11-10

**Сделано**

- `scripts/ingest/examples.ts`: разбор 18 кадров, матчинг групп к вариантам каталога
  по сэмплированным формам, определение состояния по слотам, позиция/масштаб,
  `templates.json` (18 шаблонов, 6 сцен × 3 формата).
- `relations.json`: перекрытия выпуклых оболочек (SAT), 3 связи × 3 формата.
- `stats.json`: обрезка по краям, плотность, пустая зона слева, минимальные расстояния,
  отчёт о перекраске объектов.
- Подложки `confetti`/`diagonal` извлечены **по форматам** из кадров (рисунок и
  положение различаются), fallback больше не используется.
- `tests/unit/templates.test.ts`; `pnpm facts` расширен до 18 проверок, включая
  свежесть templates/relations/stats/substrates.

**Результаты**

- Все 18 кадров сопоставлены: 0 предупреждений, масштаб всех объектов 1,0 ± 0,002.
- Состояния: `lamp.bg`, `book.bg`, `tulips.bg`; остальные объекты `main`.
- Размер: все объекты в примерах — `L` (детализация S не используется).
- Связи: `phone→book`, `puzzle→book(bg)`, `headphones→tulips(bg)`; остальные пары
  визуально стоят рядом, но оболочки не пересекаются.
- Подложки: confetti — 10 элементов, diagonal — 4; данные для square/wide/tall.

**Удивило**

- Подложки в примерах **не совпадают** с библиотечными: меняется и рисунок
  (diagonal square vs wide/tall), и положение; поэтому данные берутся из кадров.
- Книжный «лишний» путь в примерах лежит вне группы (белый/bg-light, 17×24 px)
  рядом с книгой; отбрасывается фильтром подложки и не входит в объект.
- Дизайнер перекрасил кошелёк в сцене 2: `bg-light→obj-1`, `obj-1→obj-2`
  (20–23 пути во всех трёх форматах). Это не чистая перестановка `obj-1..3`.

**Решение по ASK-03**

- Чистых перестановок `obj-1..3` нет → `slotOverride` **не реализуем** (по разделу 17).
  Перекраска кошелька зафиксирована в `stats.json.colorPermutations` как справочная;
  шаблоны отвечают только за раскладку, цвета берутся из палитры.

**Отложено**

- `scripts/ingest/fit.ts` остаётся заготовкой: подгонка живёт в `svg.ts`.

## Фаза 3. Core: перекраска, сцена, экспорт — выполнено 2026-11-10

**Сделано**

- `src/core/palette.ts`: 3 встроенные схемы, разбор JSON/full, `{bg,obj}`, списка 6/8 hex,
  CSS-переменных; автоназначение bg через OKLCH (кластер тона + светлота); валидация
  (ΔE obj/bg, порядок светлоты, контраст ink).
- `src/core/recolor.ts`: слот → hex, white → `#FFFFFF`.
- `src/core/geometry.ts`: матрицы, `anchorScale`, поворот вокруг центра bbox, hull/SAT,
  hit-test.
- `src/core/catalog.ts`: рантайм-типы каталога, `variantFor` (alias-aware), валидатор.
- `src/core/scene.ts`: добавление/удаление/дубликат/слои/состояние/масштаб/размер,
  `validateScene`.
- `src/core/export/svg.ts`: сериализация SVG с clipPath кадра, фоном, подложкой и
  объектами; `d` дословно, id `ic1-*`, один `matrix(...)` на объект.
- `src/core/export/lint.ts`: запрет растра/style/классов/url-ссылок, уникальные id,
  проверка `d` по каталогу, размеров и viewBox.
- `scripts/lint-export.ts`: проверка всех 18 экспортов примеров; добавлен в `pnpm verify`.
- Тесты: палитры, сцена/экспорт, негативные lint-тесты, золотой оракул перекраски,
  воспроизведение 18 кадров, байтовая сохранность `d`.

**Результаты**

- `lint:export`: 18/18 экспортов валидны.
- Перекраска (алгоритм из ТЗ): `assembled-L` (orange) — 6 объектов, `assembled-S`
  (teal) — 3 объекта; 100 % совпадение цветов на сопоставленных путях.
- Воспроизведение кадров (порог канала 32): все сцены ≤ 0,3 %, кроме:
  `scene-2` 19–24 % (намеренная перекраска кошелька в примере) и `scene-6` 1–1,7 %.
- Байтовая сохранность: все 1550 путей L и S в экспорте совпадают с фрагментами.

**Удивило**

- В примерах есть оттенки вне палитры (`#F5EFC9`, `#222221`, `#F9F7FB` и т.п.);
  они близки к слотам, но не совпадают. Поэтому пиксельное сравнение использует
  допуск 32 по каналу, иначе папка/кошелёк дают 30 % расхождения без геометрической ошибки.
- Кошелёк в сцене 2 действительно перекрашен (жёлтый корпус вместо bg-light) — это
  единственное крупное расхождение рендера.
- ClipPath кадра в исходнике задан в координатах листа; рендер кадра делается через
  `viewBox` со сдвигом, без transform, иначе подложка обрезается неверно.

**Отложено**

- Редактор/UI (Фаза 4), раскладка (Фаза 5), LLM (Фаза 6).
