# ARCHITECTURE

## 1. Обзор

Illustration Composer — Vite/React/TypeScript SPA + одна serverless-функция.
Вся предметная логика (источники, геометрия, палитры, раскладка, экспорт) живёт в
`src/core` и не зависит от React/DOM. UI в `src/app` — тонкий слой над `Scene`.
`src/server/compose-intent.ts` — единственное место, где вызывается LLM; для Vercel он
собирается esbuild в self-contained `api/compose-intent.js` (см. §9).

```
Figma SVG ─ingest(1 раз)→ catalog + fragments + substrates + templates + relations
                                      │
текст ─► intent (LLM | fallback | search) ─► items[] ─► layout ─► Scene (JSON)
                                                              │
                                          editor (Zustand) ◄──┤
                                                              ▼
                                   buildSceneRender ──► React canvas
                                          └──────────► SVG export
                                     recolor(Palette) ──┘
```

## 2. Границы модулей

| Слой       | Что можно                                                   | Что нельзя                                                      |
| ---------- | ----------------------------------------------------------- | --------------------------------------------------------------- |
| `src/core` | чистые функции, типы, `@xmldom/xmldom`, `culori`, `fuse.js` | импорт `src/app`, `window`, `document`, `localStorage`, `fetch` |
| `src/app`  | React, Zustand, DOM, localStorage, fetch                    | писать геометрию/экспорт в обход core                           |
| `api`      | Node/серверный код, Anthropic SDK, `process.env`            | отдавать ключ клиенту                                           |
| `scripts`  | fs, парсинг исходников, генерация `data/generated`          | быть рантайм-зависимостью приложения                            |

ESLint (`eslint-plugin-boundaries` + `no-restricted-globals`) проверяет границы.

## 3. Ingest: из Figma в каталог

Вход: `data/source/library/library-L.svg`, `library-S.svg`, страница примеров,
шесть референсов SVG-drop. Карта групп — явная, `data/curated/figma-map.json`.

1. **fixId.** Кириллические `id` в экспорте — mojibake (`&#208;…`). Декодирование
   Latin-1 → UTF-8; если появляется `�`, строка считается валидной.
2. **Группы.** По карте находятся группы `main`/`bg` для L и S. Лишние пути книги
   (`Vector_123/124` в L, `Vector_269/833` в S) отбрасываются по id; число путей
   сверяется с картой (40 комбинаций).
3. **Слоты.** Каждый `fill`/`stroke` переводится в слот по **purple**-палитре.
   Фоновые объекты обязаны использовать только `bg-*` (проверяется при ингесте).
4. **bbox/hull.** `svg-path-bbox` даёт точный bbox; hull строится по сэмплированным
   точкам и контрольным точкам, упрощается до ≤64 вершин.
5. **S→L fitting.** Подписи путей — нормализованные сэмплы по длине (32 точки).
   Совпавшие пары дают МНК равномерного масштаба и переноса; условие: ≥5 пар,
   невязка < 0.05 px. Результат — матрица `toNative` S-варианта.
6. **Alias.** Если число путей и мультимножество слотов совпадают и все S-пути
   ≥3 px нашли пару, S-рисунок не дублируется: L-вариант получает `sizes:['S','L']`.
7. **Подложки.** Из групп `Фон` (confetti, purple) и `Фон_3` (diagonal, orange);
   затем рисунок по каждому формату берётся из кадров примеров, потому что он
   меняется между square/wide/tall. `origin` + `elements` хранят дословные `d`.
8. **Примеры.** 18 кадров сопоставляются с каталогом по форме путей; состояние
   определяется по слотам; позиция — медиана сдвигов совпавших путей; масштаб
   должен быть 1.0 ± 0.002. Результат: 18 шаблонов, 6 сцен × 3 формата.
9. **Связи и статистика.** Перекрытия hull-ов (SAT) дают `relations.json`;
   обрезка/плотность/пустая зона/расстояния — `stats.json`.
10. **Проверка.** `pnpm facts` пересчитывает всё независимо и сравнивает с
    `data/generated`; расхождение — ошибка сборки.

## 4. Данные `data/generated`

| Файл                | Содержимое                                                          |
| ------------------- | ------------------------------------------------------------------- |
| `catalog.json`      | 10 объектов, 28 вариантов, `toNative`, bbox, hull, `sizes`, палитры |
| `fragments/*.json`  | массив `{d, fill, stroke, attrs}`; `d` дословный                    |
| `substrates/*.json` | `confetti`/`diagonal`, элементы по трём форматам, `origin`          |
| `templates.json`    | 18 авторских расстановок (`items[].x/y/z/state/size`)               |
| `relations.json`    | пары «верхний → нижний» с наборами смещений                         |
| `stats.json`        | параметры раскладки по форматам + отчёт о перекрасках               |

Ингест идемпотентен: `facts` сравнивает файлы байт-в-байт с результатом сборки.

## 5. Scene и координаты

`Scene` — JSON: `format`, `size`, `paletteId`, `substrate`, `scale`, `items[]`.
`Instance`: `id`, `objectId`, `state`, `x`, `y`, `rotation`.

- **Нативные единицы** = координаты листа L. `toNative` приводит фрагмент к нативному
  bbox с началом в (0,0).
- **Матрица объекта:**
  `anchorScale(s, центр кадра) ∘ translate(x,y) ∘ rotateAroundCenter(r, bbox) ∘ toNative`.
  `anchorScale` масштабирует всю сцену, не меняя пропорций.
- **S/L** — глобальный параметр сцены; выбирается вариант, у которого `sizes`
  содержит размер. Позиции в нативных координатах сохраняются.
- **Поворот** — вокруг центра bbox; UI предупреждает, что он нарушает изометрию.

## 6. Рендер и экспорт

`src/core/render.ts::buildSceneRender` — единственный источник истины:

- фон (`bg-light`),
- подложка (матрица cover/translate),
- объекты (матрица + пути уже в hex-цветах палитры).

`src/core/export/svg.ts` сериализует этот же результат. Поэтому React-холст и скачанный
SVG всегда совпадают. Особенности экспорта:

- `d` путей дословно, порядок сохранён;
- все id с префиксом `ic1-` и уникальны; объект — `<g id="ic1-obj-N-object">`;
- нет `<style>`, классов, `<image>`, фильтров, масок, `<use>`, градиентов;
- обрезка кадра через `clipPath`; объекты остаются целыми;
- `white` → `#FFFFFF`.

`src/core/export/lint.ts` проверяет перечисленное и `d` по каталогу. Он вызывается
перед скачиванием, в `pnpm lint:export` (18 шаблонов) и в тестах.

## 7. Перекраска

Фрагменты содержат только слоты. `recolor.ts` подставляет hex выбранной палитры в
`fill`/`stroke`. Встроенные схемы — purple/orange/teal; пользовательская палитра
разбирается `palette.ts`:

- JSON с 8 слотами — как есть;
- `{bg:[3], obj:[3]}` — bg сортируются по светлоте;
- 6 hex — кластер ближайших тонов в OKLCH → `bg-*`, остальные → `obj-1..3`;
- CSS-переменные.

Валидация: ΔE `obj`/`bg`, порядок светлоты, контраст `ink`/`bg-light`.

## 8. Раскладка

`src/core/layout/layout.ts`:

1. **Шаблон.** Набор запроса = набор шаблона или его подмножество (≥2), формат
   совпадает, нет зоны заголовка и `backdrop:'on'`. Позиции автора; состояния из
   запроса. Несколько кандидатов выбираются по seed.
2. **Генератор.**
   - герой — `heroId` или максимальный `heroWeight`;
   - стопки — из `relations.json`;
   - остальные — вдоль осей ±30° от центра кластера с джиттером;
   - фон — `bg`-вариант, ниже по z, обрезан краем;
   - автоскейл 0.35–1.4.
3. **Скоринг 300 кандидатов.** SAT-перекрытия (900 за запрещённое), обрезка,
   вторжение в зону заголовка (600), баланс, плотность. Выбирается минимум.
4. **Z-порядок.** Сначала фон, затем топологическая сортировка пар «верхний → нижний».
5. **Детерминизм.** `mulberry32(seed)`; одинаковый запрос + seed = одинаковый Scene.

Golden-метрика: 18/18 эталонных сцен, средняя ошибка 0.0000 px.

## 9. Ввод

### По названиям

`search.ts`: нормализация (регистр, ё→е, пунктуация), стемминг русских окончаний,
совпадения по названию/синонимам/тегам, префиксы, Левенштейн ≤2, Fuse для опечаток.
`resolveQuery` разбирает несколько названий; неизвестные возвращаются с подсказками.
Объект никогда не создаётся вне каталога.

### По смыслу

`src/server/compose-intent.ts` (→ `api/compose-intent.js`):

- `POST { text, locale }`, длина ≤200;
- лимит 20/час на IP (in-memory), кэш по SHA-256;
- RouterAI, OpenAI-совместимый `POST /chat/completions` с `Bearer`-ключом;
  модель `deepseek/deepseek-v4.1-flash-1017` (переопределяется `ROUTERAI_MODEL`);
- каталог в системном промпте; текст — данные, не инструкции;
- ответ валидируется zod-схемой и правилами (objectId ∈ каталога, 1–6 уникальных,
  ровно один hero, backdrop только bg); при ошибке один повтор;
- заголовок `x-intent-source: llm|fallback`; при ошибке/лимите/отсутствии ключа —
  локальный `fallbackIntent`.

Результат сразу уходит в `layout()`. UI показывает `fit`, `note` и пометку локального
подбора.

## 10. UI и состояние

- Zustand + immer: `Scene`, `selectedId`, `viewport`, история снимков (100 шагов),
  `layoutSeed`, `bgMode`.
- Снимки — JSON-клон (immer-draft не клонируется `structuredClone`).
- Автосохранение Scene в `localStorage['illustration-composer.scene.v1']` с debounce
  250 мс и валидацией при восстановлении; пользовательские палитры — отдельный ключ.
- Холст: hit-test по путям, drag, поворот, zoom колесом, pan пробелом, fit.
- Экспорт: `buildSceneRender` → `exportScene` → lint → download/copy.

## 12. Деплой

Vercel: статический `dist` + `api/compose-intent.js` (Node). Исходник функции —
`src/server/compose-intent.ts`; `pnpm build:api` собирает его esbuild-ом в один файл
(каталог, zod и fuse встроены), потому что Vercel не бандлит локальные модули вне
`api/`. `pnpm verify` проверяет свежесть бандла. Переменные:
`ROUTERAI_API_KEY`, `ROUTERAI_BASE_URL`, `ROUTERAI_MODEL`,
`COMPOSE_RATE_LIMIT_PER_HOUR`. Vite dev-сервер сам обслуживает `/api/compose-intent`,
поэтому ключ работает и в `pnpm dev`.
Rate limit и кэш живут в памяти инстанса; при масштабировании нужен внешний стор,
но для тестового задания этого достаточно.

## 13. Известные ограничения

- Per-object перекраска (ASK-03) не реализована: в примерах нет чистой перестановки
  `obj-1..3`, есть более широкий случай кошелька.
- Авто-раскладка не поворачивает и не отражает объекты (осознанно).
- Для точного набора эталона существует ровно один шаблон на формат, поэтому
  «Ещё вариант» на нём возвращает ту же расстановку; генератор даёт варианты для
  остальных наборов.
- Подложки из примеров воспроизводятся как есть; библиотечная версия — только square.
